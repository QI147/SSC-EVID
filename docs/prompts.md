# Prompts

Generated by `scripts/dump_prompts.py` from the exact strings the code sends; do not
edit by hand. Every prompt is a single user message: the system role is empty and the
table image is attached to the same message. JSON payloads are appended after the
prompt text, one blank line apart.

Notation: `{...}`-looking text inside a prompt is literal; the only substitution is the
appended JSON data block.

# EVID36 method

## Observe facts (initial)

`fact_first.initial`, first call.

```text
Read the question and image BEFORE answering. Return ONE compact JSON object.
Every rows entry below is an IMAGE OBSERVATION. Format:
{"question_plan":{"answer_type":"number|entity|entities|date|comparison|other",
"condition":"short predicate","selection_unit":"rows/entities/events if relevant"},
"scope":"range and limits","unresolved":[],
"rows":[["physical row","column/header","raw text",null,null]],"operations":[]}.
Each row tuple is [physical_row,column,raw_text,optional_pure_numeric_value,optional_entity].
Last two entries may be omitted. IDs i1,i2,... are assigned by tuple position;
source=image and locations are assigned by this explicit format, so do not repeat
id/location/content/source keys for every cell. Use physical row identities rather
than deduplicating equal printed labels. Record unit/header/date evidence too.
Use only relevant columns, short raw labels and raw values; no long explanations.
For scans, include relevant positive and negative observations compactly. Never
claim omitted rows complete. Prefer one row tuple per needed cell, not a transcript.
At most TWO OPTIONAL operations over the ENTIRE listed subset, never one per row.
Allowed op=sum|sub|count|count_distinct|compare|argmin|argmax|filter_gt|filter_ge,
with id=it1, evidence_ids=[i1,i2,...], threshold only for filters. Operations may be [].
Place plan/scope first and facts before optional operations. Do not give final answer.
If budget is insufficient disclose remaining range in scope/unresolved; do not invent.
```

## Initial answer

`fact_first.initial`, second call; receives the observation ledger and auxiliary results.

```text
Use your OWN observed facts and auxiliary computations to produce an initial
answer. The facts may be mistaken or incomplete; inspect the original image when
needed. Computed results are conditional on operands and range, not truth labels.
Return ONE compact JSON object:
{"answer":"...","reasoning":"brief fact-based explanation",
"supporting_ids":["i1","it1"],"scope":"coverage and remaining limits","unresolved":[]}.
Include the full requested answer: observed unit scale/currency, complete names,
qualifiers and date ranges as applicable. For example, a cell under an 'in millions'
header must preserve that magnitude in the answer; do not infer units from gold
or domain stereotypes. Cite the header fact supporting the unit. A numeric lookup
and listing matching entities are different tasks. Do not substitute counts for lists.
Do not copy a computational error from prose if auxiliary arithmetic contradicts it.
Use existing IDs. A candidate may be unverified: if the observation protocol failed,
read the original image directly and use supporting_ids=[] rather than inventing facts
or IDs. Missing metadata is not a reason to invent or withhold an otherwise defensible
candidate. If no defensible candidate exists, answer:null and disclose why.
Null/unverified/unbound records are clues only; blank is never numeric zero.
If support is insufficient keep uncertainty explicit, no fabrication.
Return the JSON directly, no preamble or Markdown. Keep reasoning to two short sentences.
Do not repeat the evidence list; cite IDs. Keep the complete requested answer and units.
```

## Support check

`evid_integrated.run`, phase `evidence_check`.

```text
Inspect the image, question, YOUR OWN initial answer, reasoning and evidence.
Initial evidence is a fallible observation, not ground truth.
Some initial records may be complete fragments of a truncated response, so range
remains OPEN. source=unverified means the legacy response did not declare a source;
it is a clue, not verified support. Add explicit image observations before relying
on such a clue to judge correct. Never infer missing rows from recovered fragments. Check it against the image.
Use c1,c2,... for NEW observations; existing initial IDs i1,i2,... may be cited but not overwritten.
If existing evidence suffices, evidence may be [], but supporting_ids must cite it. Check cells,
arithmetic, question meaning and completeness. Judge from explicit observations,
not confidence or agreement. Compare raw facts, arithmetic auxiliaries and all
qualifiers before deciding. Search explicitly for an excluded row, a lower/higher
counterexample or a unit/header contradiction. Never label correct when your own
analysis says an observation defeats the candidate. Initial scope claims are not
proof. An auxiliary result applies only to its listed operands. If operands/range
are in doubt, diagnose the gap rather than treating a computed value as the truth.
Make the finding first, then give the verdict. Return ONE compact JSON object:
{"analysis":"brief fact comparison","error_type":"...","verdict":"correct|incorrect|unknown",
"evidence":[{"id":"c1","location":"row/column/header","content":"raw observation","source":"image|calculation"}],
"supporting_ids":["c1"],"scope":"checked range or unresolved range",
"unresolved":[],"gap":null,"action":null}.
correct requires observations supporting the WHOLE requested answer and no unresolved
obligation. Both keeping and changing require evidence. If incorrect or unknown,
provide gap={"type":"VALUE|BINDING|TIME|UNIT|COVERAGE|CALCULATION|QUESTION",
"target":"specific cell/condition/range","why":"missing or contradictory support"}
and its corresponding action A_VALUE/A_BIND/A_TIME/A_UNIT/A_SCOPE/A_CALC/A_INTERPRET.
Do not generate a corrected answer yet. Missing information is unknown, not correct.
Counting rows, entities, and returning entity names are different question meanings.
Do not force lists, dates or extrema labels into counts. A claimed complete scan is
a model assertion, never a completeness certificate. Keep strings short, no prose outside JSON.
```

## Directed acquisition

`evid_integrated.run`; one directive is appended per gap type.

```text
Execute ONLY the specified evidence action on the image, using its target
and diagnostic reason. Return ONE JSON object:
{"evidence":[{"id":"a1","location":"row/column/header","content":"observation or explicit calculation","source":"image|calculation"}],
"scope":"range inspected and limits","unresolved":[]}.
Use new IDs a1,a2,...; do not repeat c IDs. Do not output an answer or a verdict.
Do not invent missing source information. Use compact relevant records, not an entire table transcription.

ACTION: <directive>
```

**A_VALUE** — Reread the specified cell and its nearby row/column labels; preserve raw characters and alternatives.

**A_BIND** — Trace the specified value to its physical row and full column/header. Distinguish entity identity from repeated event rows.

**A_TIME** — Read the specified date/interval/status and its headers. Resolve current versus historical status and inclusive boundaries.

**A_UNIT** — Read unit/header/footnote and give any explicit conversion with operands. Do not change counting objects by a unit rule.

**A_SCOPE** — Inspect the required candidate range, recording qualifying AND excluded observations compactly. State the unit of selection and omissions.

**A_CALC** — Retrieve raw operands at their locations, then redo the specified arithmetic or comparison explicitly. Preserve signs and units.

**A_INTERPRET** — Compare the question wording to table headers. Resolve selection versus count, row versus entity, negation and thresholds; keep unresolved alternatives.

## Reassess and correct

`evid_integrated.run`, phase `evidence_reassess_and_correct`.

```text
Use the question, image and updated evidence ledger to reassess the INITIAL
answer. LLM owns semantic judgment; do not rely on program source labels.
Return ONE compact JSON object:
{"verdict":"correct|incorrect|unknown","error_type":"...","analysis":"specific evidence-based finding",
"supporting_ids":["c1","a1"],"scope":"support and limits","unresolved":[],
"answer":"final candidate","reasoning":"brief evidence-based explanation"}.
If initial answer is correct, keep it. ONLY if incorrect, generate the corrected
answer based on that error and the observations. If unknown, keep initial answer
and disclose unresolved obligations. Selection/list answers must stay names/lists,
not counts. Do not let missing schema be a reason to invent a different answer.
Do not add new observations outside the ledger; any new observation needs another
acquisition which is outside this call's permission. No Markdown or long narrative.
```

## Final gate

`evid_integrated.run`, phase `recheck`.

```text
Check the candidate against the question, image and supplied evidence ledger.
Return ONE compact JSON object:
{"verdict":"correct|incorrect|unknown","analysis":"brief finding",
"supporting_ids":["a1"],"scope":"checked obligation/range","unresolved":[]}.
correct requires evidence supporting the entire requested answer, including
counting/selection unit, binding, time, units and relevant range as applicable.
Do not trust agreement or declared completeness. Do not propose another answer.
If you discover a new fact not in the ledger, disclose it as unresolved: this call
does not silently acquire or replace evidence. Missing support means unknown.
```

# Baselines and controls

## Direct read

arm `DIRECT`.

```text
Answer the question using only the supplied table image. Output only the final answer, including the unit when applicable. Do not output reasoning, evidence records, or a self-review.
```

## Second read with the previous answer

arm `REREAD2`, second call.

```text
Read the ORIGINAL image and question again. The previous answer may be wrong. Independently redo the requested reading/computation and output only your final answer with units/names. No correctness verdict, checklist or evidence record.
```

## Second read, JSON contract

used by the budget-matched reread and the ablation's no-fact-first initial.

```text
Read the ORIGINAL image and question again. The previous answer may be wrong. Independently redo the requested reading/computation and output only your final answer with units/names. No correctness verdict, checklist or evidence record. Return JSON {"answer":"...","reasoning":"brief basis for this answer"}, no Markdown.
```

## Shared initial

arm `COMMON`, the frozen starting point for repair.

```text
Answer the image question once. Return JSON {"answer":"final answer with units/names","reasoning":"brief reasoning, at most two sentences"}. Do not review, self-check, correct a prior answer or output evidence records. If impossible answer:null and explain briefly. No Markdown.
```

# Ablation prompts that differ from the method
Registered in `repro/ablation.py::PROMPT_DIFFS`.

- **NO_FACT_FIRST / initial** — 事实先行两次调用（OBSERVE + ANSWER 基于事实）整体替换为 GENERIC2 的两次读：X.COMMON 一次，再接 X.REREAD_JSON（含 previous_answer 与 previous_reasoning）。提示原文与 53/58 的 GENERIC2 逐字相同。

- **NO_FACT_FIRST / evidence_check** — 在 E36.CHECK 末尾追加两句：本样本没有初始证据账本，判定前应记录新的图像观察 c1..；若判 correct 且未记录观察，supporting_ids 可为 []。 (compatibility change)

- **GENERIC_ACQ / acquire** — 把 E36.ACQUIRE + "ACTION: " + DIRECTIVES[action] 替换为 GENERIC_ACQUIRE，不再带 ACTION 行与动作专用指令；数据段保留 question / initial_answer / diagnosis / question_plan，**因此仍含检查给出的 gap.target 与 analysis**。

- **NO_ACQ / evidence_reassess_and_correct** — 在 E36.REPAIR 末尾追加一句：本次未执行新取证，账本只有初始观察。 (compatibility change)

- **NO_ACQ / recheck** — 在 E36.RECHECK 末尾追加同一句披露。 (compatibility change)

- **NO_GATE / recheck** — 不发送该调用；候选通过与 FULL 相同的结构性校验后直接采纳。
